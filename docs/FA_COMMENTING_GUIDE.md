# استاندارد کامنت‌نویسی فارسی AS Team

این فایل قانون ثابت توسعه این پروژه است.

## قانون اصلی
- هر فایل سورس جدید یا هر فایل سورسی که ویرایش می‌شود باید توضیح فارسی واضح داشته باشد.
- در ابتدای فایل، هدف فایل، مسئولیت آن و ارتباطش با بخش‌های مهم پروژه توضیح داده شود.
- کلاس‌ها، Composableها، Widgetها، Screenها، Serviceها، Repositoryها، ViewModelها، Controllerها، DAOها و توابع مهم باید توضیح فارسی داشته باشند.
- منطق‌های غیر بدیهی، شرط‌های مهم، تبدیل داده، مدیریت State، Navigation، شبکه، دیتابیس، امنیت، مجوزها، Build و Release باید کنار کد توضیح داده شوند.
- کامنت باید «چرایی» و نقش کد را توضیح دهد؛ از کامنت‌های تکراری و بدیهی مثل «متغیر را تعریف می‌کند» خودداری شود.
- TODO/FIXME باید فارسی و همراه با دلیل و کار موردنیاز باشد.
- هنگام تغییر منطق، کامنت مرتبط نیز باید هم‌زمان به‌روزرسانی شود.

```text
// ورودی‌های مهم: ...

// وابستگی‌ها: ...
```

## استثناها
فایل‌های تولیدشده خودکار، فایل‌های باینری، lock fileها، کدهای Vendor/Third-party و فایل‌هایی که تغییر مستقیم آن‌ها توصیه نمی‌شود از کامنت‌گذاری مصنوعی مستثنا هستند. این موارد در مستندات پروژه توضیح داده می‌شوند، نه داخل خود فایل تولیدشده.

## روش اجرای پروژه
برای سورس upstream، کامنت‌گذاری هم‌زمان با فارسی‌سازی و شخصی‌سازی هر فایل انجام می‌شود تا تاریخچه تغییرات قابل پیگیری بماند و Diffهای عظیم و بی‌استفاده ایجاد نشود.

## هدف آموزشی
هر توسعه‌دهنده باید بتواند با خواندن سورس و همین کامنت‌ها بفهمد هر بخش چه کاری می‌کند، چرا وجود دارد، به کجا متصل است و برای تغییر آن باید از کجا شروع کند.
